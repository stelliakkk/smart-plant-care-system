# 当前系统架构

## 三端职责

| 部分 | 当前职责 |
|---|---|
| ESP32-S3 edge01 | 传感器采样；四路PWM执行器；本地补光；泵限时关闭、互斥、指令去重和断网停止 |
| ESP32-CAM cam01 | OV2640 1600×1200 JPEG /capture；每3秒MQTT公布相机地址 |
| FastAPI + SQLite + MQTT | 在线状态、关联指令回执、图像下载/AI分析/保存、48小时冷却、两路定时清水演示调度 |
| Vue + Vite | 总览、四路手动/自动控制、高清照片与分析历史、模式/冷却/下次执行与回执 |

图片通过HTTP下载，不经过MQTT或USB传图；COM4原生USB对应S3 JTAG/串口，COM8是CAM串口下载座。电脑、两块板需在可互通网络，broker监听1883；Wi-Fi名称相同不保证电脑IP固定。

## 数据与控制

- S3上报光照和相对土壤湿度。湿度和盐分共享ADC1，各自配置通道/电压校准；盐分原始值与DS18B20读数只保留本地采样/日志，soil_ec、temperature上报null。
- 补光：S3低于100 lux持续10秒开启，高于300 lux持续30秒关闭；无有效读数10秒停止自动灯。自动补光断网仍运行。
- 喷洒：仅连续两次定时有效照片明确虫害且有可见依据，后端下发2秒；48小时冷却持久保存，仍每5分钟拍照分析。手动抓拍不触发喷洒。
- 补水/施肥：后端每秒检查各自定时间隔，S3执行单次限时动作。同时到期按上次定时提交记录轮换优先，重启保留轮次；未配置参数不能启用，重启重新计时，离线/模式未确认/另一泵忙时跳过，不补发；不使用AI、湿度或EC决定运行。
- 遥测逐条保存data_source：device为设备上报，simulated为模拟，unknown为旧记录来源未记录。网页模拟接口强制标记simulated，模拟脚本也携带此字段；旧固件省略字段时按device接收。
- 补水和施肥在后端和板端双重互斥，涵盖手动和自动；农药泵不加入这两路的互斥组。
- 手动操作暂停对应自动模式；关闭全部先暂停四路，再下发关闭。网络停止指令不是物理断电保障。

## 持久化与兼容

SQLite旧表保留，AutomationState通过新增JSON配置字段兼容旧数据；ActuatorCommand关联command_id/boot_id。自动模式S3也存NVS。后端以单实例、单worker启动；自动化共享指令锁，避免调度/手动/心跳状态处理竞态。

旧自动补光/喷洒固件无timed_pumps_ready，后端保留原功能并阻止定时泵指令；定时参数可保存，升级后网页主动恢复自动。本次调度轮换和来源标记为后端/前端更新，无需为此重烧两块板。首次采用2 MiB分区时需连同S3应用烧录。

后端启动时自动为旧sensor_reading表补充data_source列，旧行保留为unknown，不猜测历史来源，不删除原数据。

## 当前边界

照片/分析保存7天、定时控制与回执已实现。WebSocket目前只有hello/ping/pong/echo，业务状态依靠轮询；未接传感器流量/水位/负载电流反馈，未实现实际肥液配比、湿度闭环补水、EC施肥决策或OTA。清水演示时长不能当成实际植物浇水量/施肥量。

截至2026-11-02，用户确认实物供电电路正在使用、补光灯已实测；三路泵已接线并实现逻辑，但未实测运行。软件模拟测试与实物验证分别记录。
