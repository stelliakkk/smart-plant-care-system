# 硬件接线表 —— ESP32-S3-DevKitC-1 v1.1

> 本文只回答一个问题：**哪根线插哪个孔**。烧录步骤见
> [../edge/esp32s3_plant_edge/README.md](../edge/esp32s3_plant_edge/README.md)。

## 1. 引脚分配（已确认无冲突）

| 功能 | GPIO | 为什么选它 |
|---|---|---|
| BH1750 · SCL | **GPIO5** | 空闲引脚，紧挨着 SDA，连线顺 |
| BH1750 · SDA | **GPIO6** | 空闲引脚 |
| 土壤湿度 · AOUT | **GPIO4** | 必须是 **ADC1** 的通道（`ADC1_CHANNEL_3`）。<br>ADC2 在 WiFi 工作时会被占用，**接 ADC2 的引脚读出来全是废数** |
| 土壤盐分 · AOUT | **GPIO7** | ADC1 模拟输入；输出不得超过 3.3V |
| DS18B20 · DATA | **GPIO8** | 1-Wire 数字数据线，不是 ADC；DATA 需用约 4.7kΩ 上拉到 3.3V |
| 盐水泵 · MOS 输入 | **GPIO11** | PWM 20kHz，初始化为 0%；水泵使用独立电源 |
| 农药喷雾泵 · MOS 输入 | **GPIO13** | PWM 20kHz，初始化为 0%；水泵使用独立电源 |
| 补光灯 · MOS 输入 | **GPIO15** | PWM 20kHz，初始化为 0% |
| 电源 | **3V3** | 两个模块都用 3.3V |
| 地 | **G** | 传感器、ESP32、MOS 驱动和负载电源**必须共地** |
| 板载 RGB | GPIO38 | 板子自带 WS2812，不用接线 |
| 串口 | GPIO43 / 44 | UART0，经 CP2102N 接 USB |

### 千万不要接的引脚

| 引脚 | 原因 |
|---|---|
| **GPIO35 / 36 / 37** | 被 Flash 和 PSRAM 占用，接上去直接启动不了 |
| **5V** | ★ 模拟传感器接 5V 可能把 AOUT 顶到 5V，**烧掉 GPIO4/GPIO7**（不可修复） |
| GPIO19 / 20 | USB-JTAG 复用，接了会影响下载 |

## 2. 在板子上怎么找到这几个脚

板子排针旁边都印了丝印（`3V3`、`G`、`4`、`5`、`6`…），**按丝印找最可靠**。
把 **USB 口朝下**、看**左侧那一排**：

```
   顶边（远离 USB 口）
   ┌──────────────────────────────────────
   │  3V3   ← 传感器供电（有两个，用哪个都行）
   │  3V3
   │  RST   ← 复位键旁边
   │  4     ← 土壤湿度 AOUT
   │  5     ← BH1750 SCL
   │  6     ← BH1750 SDA
   │  7
   │  15 / 16 / 17 / 18 / 8 / 3 / 46 / 9 ...
   │  ...
   │  5V    ← ★ 别碰这个
   │  G     ← 共地（有两个）
   │  G
   └──────────────────────────────────────
   底边（USB-C 口在这边）
```

**一句话记忆**：`RST` 下面紧挨着的三个数字脚 `4`、`5`、`6`，就是我们要用的。

## 3. 接线表

### 3.1 BH1750 光照模块（GY-302）

GY-302 模块上一般有 5 个针（丝印可能是 `VCC GND SCL SDA ADDR`，也可能是 `VCC GND SCL SDA ADD`）：

| 模块针脚 | 接到开发板 | 备注 |
|---|---|---|
| `VCC` | **3V3** | 3.3V。模块虽支持 5V，但保险起见别用 |
| `GND` | **G** | |
| `SCL` | **GPIO5** | I2C 时钟 |
| `SDA` | **GPIO6** | I2C 数据 |
| `ADDR` | **不接（悬空）** | ★ 器件的"门牌号"：悬空 = `0x23`（低电平），<br>接 VCC = `0x5C`。**必须悬空**，代码按 `0x23` 找它 |

### 3.2 电容式土壤湿度模块

常见的是 teljesky 电容式 v2.0，3 个针：

| 模块针脚 | 接到开发板 | 备注 |
|---|---|---|
| `VCC` / `+` | **3V3** | ★★ 接 5V 会烧 GPIO4 |
| `GND` / `-` | **G** | 和 BH1750 用同一个 G |
| `AOUT` / `S` | **GPIO4** | 模拟量输出，进 ADC |

> 有的模块是 `GND / VCC / AOUT` 顺序，有的是 `+ / - / S`，**按模块上的丝印走**，
> 别按位置猜。接反电源会烧模块。

### 3.3 完整连接示意

```
                    ┌─────────────────────────┐
                    │  ESP32-S3-DevKitC-1     │
                    │                         │
   ┌── 3V3 ─────────┤ 3V3                     │
   │                │                         │
   ├── G  ──────────┤ G                       │
   │                │                         │
   │  ┌─ GPIO5 ─────┤ 5                       │
   │  │             │                         │
   │  │  ┌─ GPIO6 ──┤ 6                       │
   │  │  │          │                         │
   │  │  │  ┌ GPIO4 ┤ 4                       │
   │  │  │  │       │                         │
   │  │  │  │       │        (USB-C 朝下)     │
   │  │  │  │       └─────────────────────────┘
   │  │  │  │
   │  │  │  │        ┌──────────────┐
   │  │  │  └────────┤ AOUT         │
   │  └──┼──┼────────┤ SCL   BH1750 │
   │     └──┼────────┤ SDA   (GY-302)│
   └────────┼────────┤ GND          │
            │        │ VCC          │
            │        │ ADDR  ← 空着 │
            │        └──────────────┘
            │
            │        ┌──────────────┐
            └────────┤ VCC          │
                     │ GND  土壤湿度 │
                     │ AOUT  电容式  │
                     └──────────────┘
```

（两块模块的 GND 都回到板子的 `G`；两块模块的 VCC 都回到 `3V3`。）

### 3.4 建议的线色约定

线多了一起很容易接错，按颜色区分能省很多事：

| 颜色 | 用途 |
|---|---|
| 红 | 3V3 电源 |
| 黑 | GND |
| 黄 | I2C SCL |
| 绿 | I2C SDA |
| 蓝 | 模拟量 AOUT |

## 4. 动手顺序

```
① 先拔掉 USB（千万不要带电插拔试验）
② GY-302 若是"未焊接排针"款，先把排针焊好，焊完检查有没有连锡
③ 用面包板过渡，先接电源（红/黑），再接信号（黄/绿/蓝）
④ 接完**对照第 3 节的表逐根核对一遍**，特别是 3V3 和 5V 别弄混
⑤ 插 USB，看板子上的电源灯亮不亮
⑥ 烧录固件，看串口日志里两个传感器是否都识别到
```

## 5. 常见坑

| 坑 | 现象 | 处理 |
|---|---|---|
| 土壤模块接了 5V | GPIO4 永久损坏，之后读数恒为 4095 或 0 | 只能换引脚重接，**接线前务必核对** |
| 忘记共地 | 光照正常，土壤读数乱跳（在 0 和 4095 之间反复横跳） | 两个模块的 GND 都接到板子 `G` |
| `ADDR` 接了 VCC | 日志报 `BH1750 不在 0x23 (ESP_ERR_NOT_FOUND)` | 把 `ADDR` 拔掉悬空 |
| SCL / SDA 接反 | 同样报 `ESP_ERR_NOT_FOUND` | `SCL→GPIO5`、`SDA→GPIO6` |
| 杜邦线太长（>20cm） | 时好时坏，扫描不到器件 | 先用 **100kHz** 低速率，缩短连线 |
| 干燥时读数卡 4095 | 探头在空气里，输出电压超出量程（约 3.1V） | 属正常现象；需要测"更干"的土时加 2:1 分压 |
| 探针泡水 | 读数漂移、电路板腐蚀 | 只插土，白色电路部分和插头不能进水 |
| 读数永远卡 0% 或 100% | 标定端点填反，或探头没插好 | `soil_sensor_init()` 会拒绝 `mv_dry ≤ mv_wet` 的配置并报 `ESP_ERR_INVALID_ARG`；先查 `main/local_config.h` 第 3 节 |

> 大多数电容式土壤模块板载了 4.7kΩ 上拉电阻。若你的批次没有，
> 固件里已开启 ESP32 内部上拉兜底 —— 所以接线正确的话一定能读出来。

## 6. 接完怎么自检

不用万用表，**烧录固件看串口日志**即可。

### 6.1 开机自检（前 0.5 秒）

```
I (331) I2C_BUS: Init I2C master bus: SCL=GPIO5, SDA=GPIO6, 100000 Hz
I (341) LIGHT: BH1750 found at 0x23                          ← ① 探活成功
I (351) LIGHT: BH1750 ready (单次高分辨率模式, 1 lx, 每次约 180 ms)
I (351) SOIL: 土壤探头: GPIO4 = ADC1 通道 3                   ← ② 引脚自动映射
I (361) SOIL: ADC 曲线拟合校准已启用
I (361) SOIL: 土壤探头就绪 (生效标定端点: 干燥 2200 mV / 湿润 1100 mV; 悬空应≈0%, 泡水应≈100%)
```

看到 ① 就说明 BH1750 接线（含上拉、地址）全对；看到 ② 说明 GPIO4 被正确识别成 ADC1 通道。

### 6.2 每秒采样行

```
I (561) APP: light=   65.0 lux | soil=raw=2559 2188 mV   2.0 % | heap=385208 B
```

| 字段 | 含义 |
|---|---|
| `light=` | BH1750 读数，单位 lux |
| `soil=raw=` | ADC 原始值（0~4095）—— **标定时要看这个** |
| `xxxx mV` | 校准后的真实电压 |
| `xx.x %` | 换算出的含水量 |
| `heap=` | 剩余内存，正常在 380 KB 上下且稳定不降 |

### 6.3 出问题时看哪里

坏消息会明确告诉你坏在哪，而且**不会重启板子**（读失败只告警，下一周期自动重试）：

```
E (341) LIGHT: BH1750 不在 0x23 (ESP_ERR_NOT_FOUND)。请检查: SDA=GPIO6 / SCL=GPIO5
               是否接反、VCC 是否接在 3.3V、ADDR 是否被接到了 VCC(那样地址会变成 0x5C)
W (1561) APP: 读光照失败: ESP_ERR_TIMEOUT
```

日志里出现 `light=     -- lux` 或 `soil=raw=  --    -- mV` 就表示那一项没读到，
**另一项仍照常工作**——这正是"初始化失败要拦、运行期失败不拦"的设计。

### 6.4 ★ 标定土壤探头（想让数字准，这一步必须做）

干/湿两个端点决定"读到多少 mV 算多少湿度"。
驱动里只留了一组**兜底默认值**（`2600` / `1300`，仅保证能算、不代表准），
真正生效的值来自 **`main/local_config.h` 第 3 节** —— 和 WiFi 密码放在同一档的
"本机私有配置"，因为它只对**你这支探头 + 这批土**负责。
驱动代码 `components/soil_sensor/soil_sensor.c` 一个字都不用改。

端点的经验范围（公开资料）：
DFRobot SEN0193 规格书 —— 供电 3.3~5.5V、输出 0~3.0V；
常见的电容式 v1.2 教程 —— 空气中约 2.6~3.0V、浸入水中约 1.2~1.3V，
跨度约 1.1~1.4V。**同款探头不同批次差几百 mV 很常见**，
而差 300 mV 就是十几个百分点的误差。

```
① 探头悬空放在空气里, 看串口里的 mV(例如 2188)          → 填给 LOCAL_SOIL_MV_DRY
② 探头泡进一杯清水(只泡白色探头部分! 插头和电路板不能进水),
   看串口里的 mV(例如 1200)                             → 填给 LOCAL_SOIL_MV_WET
③ 改 main/local_config.h 第 3 节的那两个宏, 重新执行
   idf.py -p COM3 build flash
```

**判断标准（不用记数字，看百分比就行）**：
探头悬空应显示 **≈ 0%**，泡在清水里应显示 **≈ 100%**。
只要这两个端点对上了，中间就是线性的。

> 标定之前别急着插进土里判断"土干不干" —— 很可能只是端点没标对。

本机实测（2026-09-13，同一支探头悬空在空气中）：

| 端点设置 | 串口读数 | 结论 |
|---|---|---|
| 2600 / 1300（兜底默认） | 31.7 % | ❌ 明明在空气里，却说"土有三分之一湿" |
| **2200 / 1100（按实测标后）** | **2.0 %** | ✅ 正确 |

实测悬空电压是 **2188 mV**，比资料标称的 2.6~3.0V **明显偏低** ——
这恰好说明"照抄默认值会错得离谱"，端点还是得自己测一遍。

> 上层传进来的端点会被 `soil_sensor_init()` 校验：
> `mv_dry` 必须大于 `mv_wet`。填反了直接返回 `ESP_ERR_INVALID_ARG`
> 并在日志里点名，不会默默算出一堆假数。

## 7. 执行器引脚与上电验证

下列执行器由 ESP32-S3 通过 MOS 驱动控制；水泵使用独立电源。固件启动时会依次执行短时硬件验证，之后自动关闭：

| 执行器 | 引脚 | 上电验证 |
|---|---|---|
| 补水泵 | **GPIO9** | 20kHz、50% PWM，运行 5 秒后关闭 |
| 盐水泵 | **GPIO11** | 20kHz、50% PWM，运行 5 秒后关闭 |
| 农药喷雾泵 | **GPIO13** | 20kHz、50% PWM，运行 5 秒后关闭 |
| 补光灯 | **GPIO15** | 20kHz、100% PWM，点亮 5 秒后关闭 |

安全规则（水泵最长抽水时间、喷雾每日上限）**实现在板子本地**，
不依赖后端 —— 见 [architecture.md](architecture.md) 第 4 节。
