# 自动补光与虫害喷洒

## 范围与默认状态

仅补光灯 GPIO15、农药泵 GPIO13 增加自动逻辑。补水/施肥仍手动；盐分和温度不上报。
首次使用两路自动模式均关闭。S3 用 NVS 保存两路模式，后端用新增 automation_state 表保存期望模式、冷却和最近100条判断事件，旧表无需迁移。后端单实例、单 worker 运行，电脑时间应准确。

## S3

- 主采样任务将 BH1750 读数交给执行器控制任务；所有 GPIO 驱动调用仍在同一控制任务内。
- 低于3000 lux 连续10秒开灯；高于4000 lux 连续30秒关灯；中间保持。无效/超过3秒未采样会中断阈值累计，10秒无有效读数关闭自动灯并报告异常。自动补光断网仍运行。
- 手动操作暂停对应自动模式；模式改变会清除判断计时，补光灯先关闭再重新判断。
- source=auto 仅允许 spray/on/2000ms，且板端自动喷洒模式已开启。其他泵和灯的远程自动动作拒绝。板端本地计时到期关闭；断网停止喷洒，关闭失败持续重试。
- 继续检查boot_id、非retain、指令有效期和重复command_id。指令不代表实际流量反馈。

## 后端

- 每300秒拍照分析、照片/结果保留7天的原调度继续使用，CAM固件与接口不变。
- Analysis 增加 pest_status=detected/suspected/none/unknown 与 pest_evidence；旧结果缺字段按unknown，不触发。通用has_issue不触发喷洒。
- 仅相邻定时任务明确detected且证据非空可累计。分析失败、疑似/未知、离线、模式未确认、泵状态非明确关闭会清零。手动抓拍不计数。
- 照片分析完成时超过180秒视为过期；拍摄间隔超过配置周期+60秒（最低360秒）不构成连续两次。开启模式、服务启动或S3启动会话变化均清零；旧照片不进入新周期。
- 满两次只发布一次2000ms指令，不重试喷洒。发布前持久化冷却预留，避免快速回执或后端崩溃后再次喷洒。
- 确认running从确认时间冷却48小时；未收到回执/执行失败保留保守冷却；明确未发布、拒绝或output_start_failed恢复此前冷却（不会清除前一次真实喷洒冷却）。done继续冷却。
- 冷却结束仅接受冷却结束后的新照片重新累计。手动喷洒允许在冷却期间主动操作，更新冷却；手动拒绝不删除原冷却。
- 手动操作暂停对应自动模式；关闭全部先暂停两路再发送四个关闭动作。网络不可达时，模式期望保存，待心跳恢复后同步；离线时无法保证网页停止指令送达。

## API与网页

- GET /api/device/automation：期望模式、板上模式、光照/异常、连续次数、冷却截止/剩余时间、最近喷洒回执、判断事件。
- POST /api/device/automation：{actuator: spray|grow_light, enabled: boolean}。保存期望状态；设备心跳确认实际状态。旧S3不支持自动化时不发布自动指令。
- 内部模式指令action=auto_on/auto_off，source=manual，duration_ms=0；沿用现有指令主题和回执。外部/device/command不允许绕过自动规则。
- 新心跳：automation_ready、automation对象、light_lux、light_fault。
- 控制页提供分别暂停/恢复自动，展示计数、冷却、回执与事件。事件链接GET /api/vision/record/{id}查看对应照片和虫害依据；过期照片404。

## 启用步骤与验证边界

重启后端自动创建新表，后续烧录新版S3后在网页主动恢复自动；CAM无需重烧。首次硬件联调用清水确认2秒动作和流量。2秒/48小时是demo参数，不是药剂剂量或实际用药间隔的结论。

本轮不烧录、不向实际输出发送测试、不调用付费API；后端测试用临时SQLite和模拟MQTT/HTTP。软件测试和编译不能替代现场传感器摆放、灯光反馈、泵流量与断网停止验证。应用分区约剩5%，构建仍成功。
